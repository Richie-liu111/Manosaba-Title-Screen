## 一、原游戏参考

### 功能 1：LoadGame 锁定态

**证据**：`TitleUI.prefab` 中 `Button_LoadGame` 有四个子状态容器：`Normal`、`Highlighted`、`Locked`、`Label@ZhHans`。有存档数据时用 Normal/Highlighted，无存档时用 Locked。

**素材**：`button_loadgame_locked.png` = **498×323，与 Normal 完全同尺寸** → 可直接 1:1 替换，无需改布局。

**行为**：Locked 态无悬停高亮、不可点击（原游戏按钮 Locked 即 non-interactable）。

### 功能 2：入场模糊效果

**证据**：`dump_format/System/System_Title.nani` 完整标题入场流程：

```
@bgm "Bgm_36_1"                                    ← BGM 与入场同步开始
@back Overlay SolidColor #000000 time:0            ← 全屏黑幕（覆盖整个画面）
@back 背景图 pos:50,50 Id:"Stills" Scale:1.05 time:0
@blur "Stills" power:1 time:0                      ← 初始满模糊
@animate Stills Scale:1.0 easing:EaseOutQuad time:2.7
@blur "Stills" power:0 time:2.7                    ← 2.7s 内模糊归零 + 缩放至 1.0
@back Overlay Transparent tint:#000000 time:1.8    ← 黑幕 1.8s 淡出
@Wait "i3"                                         ← 总时长 3s
@ShowUI TitleUI                                    ← 之后 UI 才出现
```

**时间线还原**（当前代码与之一一对照）：

| 时刻 | 原游戏 | 当前 forge-1 | 差异 |
|---|---|---|---|
| 0ms | 黑幕 + 背景 1.05× 满模糊 + BGM 起 | 黑底 letterbox + 背景 1.1× | 无模糊、黑幕不覆盖全屏 |
| 0–2700ms | 缩放 → 1.0（EaseOutQuad），模糊 → 0 | 缩放 → 1.0（线性）2500ms | 无模糊、缓动不同 |
| 0–1800ms | 全屏黑幕淡出 | 无 | 缺失 |
| ~3000ms | TitleUI 淡入 | UI_DELAY=2750+500 | 基本一致 |

背景选择：`{ g_gameProgress < 6 ? "1_1" : "2_1" }` —— 即现配置的 HIRO/EMA 切换（进度 <6 用希罗，之后用艾玛），与现有配置功能吻合，无需改动。

**背景裁切模型确认**（用户实测数据）：游戏窗口模式只提供 16:9 分辨率档（1440×810 / 1366×768 / 1280×720，参考分辨率 2560×1440），窗口模式与背景完全贴合无黑边，全屏（14 寸 M5 MacBook Pro，系统 1512×982 ≈ 16:10.4）时上下出现黑边。

→ 推论：画布固定 16:9（2560×1440 参考），min-fit（expand）缩放 + 非 16:9 屏幕时信箱化；2:1 背景贴图以充满画布的方式裁切。**任何时刻可见区域都不是原图完整大小**：1.0× 时 = 2:1 图的 88.89% 宽 × 100% 高（= 现有 renderBackgroundCrop 的模型，正确，不改）；1.05× 起点 = 84.65% 宽。动画是"由放大到正常"的缩放揭示过程，而非显示更多画面。

## 二、实现方案

**总原则**：`com.img` 引擎核心零改动（三项功能全部在屏幕层实现）；不动配置与声音注册。

### 功能 1：LoadGame 锁定 —— [ManosabaTitleScreen.java](src/main/java/me/shiiyuko/manosaba/gui/screen/ManosabaTitleScreen.java)（initButtons）

```java
// initButtons() 顶部，一次检查
boolean loadLocked = Minecraft.getInstance().getLevelSource()
        .getLevelList().getLevels().isEmpty();
```

- locked 时 LoadGame 按钮：`normal = highlighted = BUTTON_LOAD_GAME_LOCKED`（纹理相同 → 无悬停高亮）、`clickSound = null`、`onClick` 空操作、不设 label 纹理。
- 无需改 TitleScreenButton（同尺寸纹理直接双态替换）。
- 注意 `init()` 在 resize 时会重跑 → 每次重新检查（开销同 vanilla SelectWorldScreen 构造，可接受）。

### 功能 2：入场模糊 + 时间线对齐 —— ManosabaTitleScreen.java

1. **参数对齐原游戏**：
   - `BG_DURATION` 2500 → **2700**
   - 初始缩放 1.1 → **1.05**，缓动改为 **EaseOutQuad**：
     ```java
     backgroundLayer.setScaleFunction((t, now) -> 1.0f + 0.05f * (1 - t) * (1 - t));
     ```
   - `UI_DELAY` 2750 → 2700（UI_DURATION 500 不变）

2. **模糊效果（离屏低分辨率渲染 + 上采样）**——首选方案：
   - 创建一个低分辨率 RenderTarget（如 320×180，16:9，固定尺寸不随窗口变），将背景（含当前缩放裁切）渲染进去，再以线性过滤放大回屏幕 letterbox 区域。低分辨率纹理 + 线性插值放大 = 平滑的高斯式模糊（与 Satin / 新版原版暂停菜单模糊同技术，跨平台 GL 3.2 core 兼容）。
   - 动画：模糊版覆盖在清晰版之上，alpha = blurPower（1 → 0，2700ms）。blurPower=1 纯模糊，=0 纯清晰，中间连续过渡。
   - 实现注意：切换 RenderTarget 后需恢复 `RenderSystem.viewport` 与主 render target；渲染发生在 scissor（letterbox）区内，FBO 纹理 quad 与 letterbox 矩形同宽高比，无需额外裁剪。
   - 备选方案（不首选）：预生成模糊背景贴图交叉淡化 —— 零 GL 风险、实现最简单，但模糊程度只能分级交叉淡入（2~3 档），动画平滑度略逊。
   - ~~多遍偏移采样~~（已否决：本质是盒式滤波器近似，遍数不足时颗粒感/空心感明显，非真模糊）

3. **全屏黑幕淡出**：新增一个全屏黑色 quad，alpha 1 → 0，时长 1800ms（覆盖整个窗口，含 letterbox 外区域，对应 `@back Overlay`）。黑幕画在所有元素之上（UI 出现于 3s 后，与黑幕无交叠冲突）。

4. BGM：不动（vanilla MusicTicker 经 MusicsMixin 播放，屏幕出现即起，与原游戏 BGM 同步开始一致）。

### 功能 3：BootLogoScreen —— 新文件 + [MinecraftMixin.java](src/main/java/me/shiiyuko/manosaba/mixin/MinecraftMixin.java)

**新文件** `gui/screen/BootLogoScreen.java`：

- `extends Screen`（**非 TitleScreen** —— 1.20.1 菜单音乐由 MusicTicker 驱动且只在标题类屏幕运行，Logo 阶段保持安静，与原游戏一致：BGM 在 System_Title 才开始）
- 2560×1440 设计空间（与标题屏一致的 VirtualScreen letterbox）：
  - 黑底全屏
  - BrandLogo 787×309：中心 + (−552, +24)
  - CompanyLogo 1000×223：中心 + (+536, −32)
- 时间线：淡入 500ms → 停留 2500ms → 淡出 500ms（共 3.5s）
- 跳过：任意键 / 鼠标点击（对应原游戏 Background Button）
- 结束（自然结束或跳过）→ `mc.setScreen(new ManosabaTitleScreen())`，随后触发标题入场动画（功能 2 的模糊缩放）

**MinecraftMixin.java 改动**：

```java
// Manosaba 内新增（或放 BootLogoScreen 静态字段）：
public static boolean bootSequencePlayed = false;

@ModifyVariable(method = "setScreen", at = @At("HEAD"), ordinal = 0, argsOnly = true)
private Screen manosaba$replaceTitleScreen(Screen screen) {
    if (screen instanceof TitleScreen && !(screen instanceof ManosabaTitleScreen)) {
        if (!Manosaba.bootSequencePlayed) {
            Manosaba.bootSequencePlayed = true;   // 构造即置位，防重入/防循环
            return new BootLogoScreen();
        }
        return new ManosabaTitleScreen();
    }
    return screen;
}
```

- `bootSequencePlayed` 在 BootLogoScreen 构造时置 true → 无论自然结束、跳过还是异常路径都不会重复播放。
- 会话内只播一次：之后从世界返回标题 → 直接 ManosabaTitleScreen。
- `@Redirect(new TitleScreen)` 兜底路径返回 ManosabaTitleScreen（不播 logo）——可接受（该路径极少触发）。
- 无递归风险：BootLogoScreen 结束时的 `setScreen(ManosabaTitleScreen)` 中 ManosabaTitleScreen 被 instanceof 排除。

**SplashOverlayRenderer.java 同步修正布局**（资源包加载/切语言时也显示）：

- 1920×1080 @ 0.5 缩放 → 2560×1440 原生尺寸、原游戏坐标（(−552,+24)/(+536,−32)），两处共用同一布局。

### 功能 4：ExitDialog —— 新文件（或 ManosabaTitleScreen 内嵌）

**新文件** `gui/screen/ExitDialog.java`，作为 ManosabaTitleScreen 的子面板（同一 Screen 内，对应原游戏对话框叠在 TitleUI 上）：

**元素**（复用引擎，全部 2560×1440 设计空间）：
- `Layer` dialogbase 2560×1440（不透明全屏）
- `Layer` topframe 2560×429 顶部 / bottomframe 2560×429 底部
- 消息文本：`font.drawString` 居中 (1280, 270)，文案按 locale：
  - 简中 "真的要退出游戏吗？"
  - 日文 "ゲームを終了しますか？"
- 两个 `TitleScreenButton` 505×120（buttonbase_default / _highlighted）：
  - 是/はい：中心 (745, 510) → 左上 (492.5, 450)
  - 否/いいえ：中心 (1310, 510) → 左上 (1057.5, 450)
  - （ResponseButtons 容器 2560×144 内居中成组，间距 60px；子按钮为运行时实例化，prefab 无坐标，此为合理还原）

**交互**：
- Exit 点击 → 对话框可见 + 150ms 淡入；对话框打开期间屏蔽其他按钮交互与 ESC 返回
- 是 → 全屏黑幕 1.2s 淡入（对齐 QuitGame 时序）→ 停止 BGM（`mc.getSoundManager().stop()`，vanilla MusicTicker 无淡出 API，先直接停）→ `mc.stop()`
- 否 / ESC → 150ms 淡出关闭
- ManosabaTitleScreen 的 `mouseClicked` / `keyPressed` 优先派发给对话框

**ManosabaTitleScreen 改动**：`case "Exit" -> mc.stop()` 改为 `exitDialog.open()`；渲染顺序：背景 → 层/按钮 → 版本号 → 黑幕 → 对话框。

## 五、风险与备选

| 风险 | 对策 |
|---|---|
| FBO 切换的 GL 状态管理（viewport/render target 恢复、macOS GL 3.2 core 兼容性） | 严格保存/恢复 RenderSystem 状态；先最小实现（静态模糊）验证再接入动画；备选预模糊贴图交叉淡化 |
| `getLevelList()` 首次调用耗时 | 与 vanilla SelectWorldScreen 同量级，可接受；可延迟到首帧 |
| MusicTicker 在 logo 阶段的真实门控行为未验证 | BootLogoScreen 继承 Screen 而非 TitleScreen，无论门控如何都不会播放菜单音乐 |
| 对话框素材语义偏差（dialogbase 不透明全屏图的具体画面未知） | runClient 实测截图对照原游戏；如 dialogbase 含装饰框则以其为准微调布局 |
